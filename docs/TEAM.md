# 团队协作

产品在各自机器上管理需求、原型和发版，通过 Git 与团队主机交换数据。游客、研发和测试使用浏览器访问团队主机，无需安装 Flowlark，可选择微信登录或游客访问。

## 主机准备

1. 在团队主机打开数据仓库，配置与产品端相同的 Git 远端。
2. 从本机浏览器进入「设置 → 团队协作」，在「访问设置」开放局域网访问。
3. 按页面提示重启服务后，在同一页复制实际工作台地址，提供给团队。
4. 在「协作方式」选择「只读分享」或「角色协作」。默认只读；需要评论、开发进度和测试结果时选择角色协作。

网络开关需要重启生效；协作方式立即生效。页面区分当前运行状态与已保存配置，尚未开放时不会把地址显示为可访问。旧的「局域网分享」页面自动跳转到这里，Git 远端设置仍独立保留。

只读分享无需选角，只能浏览和下载，也能查看已保存的协作记录。切换到只读后，旧页面的写请求同样被拒绝；切回角色协作会恢复浏览器之前的角色。旧 `server.readonlyFromLan=false` 配置不会绕过新的服务端操作权限。

协作方式只保存在当前主机，不通过 Git 自动开启其他机器。产品独立部署可继续按原方式使用。永久只读镜像不能作为协作写入主机。

产品本机无需开启团队模式，也能在版本的「团队协作」页签读取 Git 同步回来的记录并发表评论。

## 角色协作的角色与入口

| 角色 | 操作 |
|---|---|
| 游客 | 浏览全部项目、下载已有原型和附件、发表评论 |
| 研发 | 基础浏览、评论、下载，以及提交开发进度 |
| 测试 | 基础浏览、评论、下载，以及提交测试问题、验收结果 |
| 产品／本机操作者 | 沿用现有需求、原型、发版和 Git 操作；在主机管理远程访客角色 |

远程首次进入只能选择游客、研发或测试，不能选择产品。确认后会记住角色；需要变更时联系主机操作者，在「设置 → 团队协作 → 访问者角色」中调整。已有页面最多约 10 秒刷新角色显示，服务端写入检查即时使用最新角色。

游客访问按浏览器分别记忆角色，同 IP 多人不会互相覆盖。IP 只作为主机列表的辅助信息；游客身份不提供真实人员认证。微信登录通过授权验证账号，首次登录仍需选角，再次登录保留主机分配的角色。一个微信账号在当前主机保留一个有效登录会话，新登录会使旧凭据失效。页面支持退出登录或切换访问方式。

角色管理仅对直接访问主机本地回环地址的操作者开放。带转发头的代理请求按访客处理；不要使用删除访客来源信息的本机反向代理来转发团队访问。

## 配置微信登录

在启动 Flowlark 的服务进程中设置以下环境变量，重启后生效：

- `FLOWLARK_WECHAT_APP_ID`：微信开放平台网站应用 AppID。
- `FLOWLARK_WECHAT_APP_SECRET`：对应 AppSecret，仅保存在服务端环境中，不写入 Git。
- `FLOWLARK_WECHAT_CALLBACK_URL`：`https://你的域名/api/team/wechat/callback`，使用该域名访问工作台；需在微信开放平台登记对应授权回调域名。

配置完整且回调地址有效时，角色协作入口启用「微信扫码登录」。未配置时显示未开通提示，仍可游客访问。当前接入网站应用扫码登录，未提供手机号或密码登录。

站点需提供 HTTPS，并反向代理至 Flowlark 工作台端口。代理须保留原始 Host、设置 `X-Forwarded-Proto: https` 并设置访客来源转发头，确保代理流量按远程访问鉴权。微信授权仅识别用户身份，不授予产品或主机权限。授权成功后首次选择协作角色；游客与账号分别保留记录，不自动合并。

登录成功或取消授权后会返回原先打开的工作台页面。授权失败可重新扫码或切换游客访问；只读模式下已登录账号也可以退出。

回调校验五分钟有效、绑定浏览器且只能使用一次的授权状态。微信 access_token 仅用于当次服务端资料查询，不返回浏览器、不写入缓存；本机缓存保存账号标识的哈希、昵称与角色。会话有效期与浏览器 Cookie 一致，最长一年，服务端同时检查到期时间；退出会立即作废凭据。服务重启会使尚未完成的扫码失效，重新登录即可。

接入参考：[微信网站应用登录开发指南](https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Wechat_Login.html)。真实扫码需使用已开通的网站应用凭据验证；自动化测试使用模拟微信响应。

## 提交协作记录

打开「项目 → 原型版本 → 团队协作」页签，选择当前角色允许的记录类型，填写并提交。记录显示类型、角色、访客短标识及时间；不会覆盖他人的已有记录。

测试验收在本轮实现为与原型版本关联的文字结果记录，不自动修改基线、迭代状态或替代正式验收门禁。使用当前已有的发版流程完成正式交付。

## 同步与恢复

主机与产品端继续通过现有 Git 操作人工同步。本轮不增加定时拉取、推送或对外通知。

- 每条协作记录独立保存在 `.flowlark/collaboration/<记录ID>.json`，随 Git 同步。独立新增记录可同时保留。
- 角色、浏览器凭据和 IP 保存在被 Git 忽略的 `.flowlark/cache/team.json`，不会发给其他产品工作区。
- 服务重启保留角色和协作记录。主机迁移若需要保留浏览器角色映射，需单独保留本机缓存；不要把它提交到 Git。
- Git 冲突继续使用现有 Git 面板处理。切换到只读分享不会删除角色记录或历史协作记录。

## 开发验证

权限与数据往返：`node --test test/team-api.test.js test/wechat-login.test.js`。

构建 Web 后，可运行 `node scripts/smoke-team.mjs` 验证主机开关、远程选角、评论、角色恢复、主机改角、测试结果、移动端布局及接口拒绝。环境需有 Playwright；可用 `PLAYWRIGHT_MODULE` 指定模块绝对路径，`CHROME_PATH` 指定 Chromium/Chrome，`TEAM_SMOKE_OUTPUT` 指定证据目录。脚本只使用临时数据仓库。

登录端到端验证：构建 Web 后运行 `node scripts/smoke-login.mjs`。使用临时仓库及模拟微信服务，验证桌面/手机入口、游客选角、账号选角、取消重试、回调 Cookie、返回原页面、刷新保留会话和只读模式退出。可通过 `PLAYWRIGHT_MODULE`、`CHROME_PATH` 指定浏览器依赖，通过 `LOGIN_SMOKE_OUTPUT` 指定截图目录。模拟测试不代替已开通微信网站应用的真实扫码联调。
