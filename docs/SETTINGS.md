# 设置中心

设置中心按任务分为六组，旧设置地址仍可使用，并会定位到对应子页。

| 分组 | 功能 |
|---|---|
| 通用 | 日常时间显示、常用标签 |
| 工作区与同步 | 工作区注册与克隆、Git 远端、提交身份、Git 助手 |
| 团队与访问 | 局域网访问、协作方式、访问者角色 |
| 集成与通知 | 外部需求/迭代/扩展连接、反馈平台、通知渠道、需求链接模板 |
| 版本规则 | 基线锁定、变更日志要求 |
| 维护与诊断 | 软件更新、回收站、最近操作日志、上传限制、索引重建 |

## 保存与生效

- 文本、列表和平台选择修改后点击“保存设置”，或点击“取消修改”。输入框失焦不会提交。
- 分组内及设置中心各分组间切换会保留普通配置草稿；关闭或刷新页面时提示未保存输入。离开设置中心前应保存或取消，草稿不会写入磁盘。
- 配置接口逐项保存。发生部分失败时，页面明确说明已保存项数，保留其余输入供重试；不会宣称整组操作具有事务性。
- 规则开关即时保存。关闭高风险规则仍需确认，失败后保留已保存状态。
- 服务类配置保存后显示重启提示。局域网页面区分当前运行状态与已保存配置。
- 工作区配置保存在 `flowlark.json`；工作区注册表、平台凭据分别使用既有本机存储。不要将令牌填入普通配置字段。

## 通用与 Git

时间偏好用于日常列表和详情，操作日志仍显示完整时间。常用标签会作为版本标签的推荐选项，不自动修改历史版本。

Git 身份页面显示 Git 实际读取到的身份，包含继承值。清空或恢复身份默认值会移除仓库级覆盖，不修改全局 Git 身份。同步与冲突处理复用 Git 助手。

“自动提交”和“默认分支”尚无完整执行链路，因此不再显示控件；历史配置键保留兼容，不会因升级而触发自动操作。当前分支可在 Git 助手中查看。

## 集成与通知

先选择平台，填写目标并保存，再保存本机凭据和测试连接。

- GitHub/Gitee 填组织与仓库；GitLab 填项目 ID 或路径；自建平台可配置 API 根地址。
- Issue 连接测试验证连接及身份，不创建 Issue，也不代表已经验证目标项目的写权限。
- 通知发送测试会实际发出一条消息。界面先显示平台、目标来源及模板，由用户明确确认。
- 企业微信会话 ID 非空时，现有发送规则优先使用 CLI；改用 Webhook 需清空会话 ID。正式发版邮件的收件人和模板继续由项目维护。
- 已保存凭据不回显，留空不覆盖。移除本机凭据不会移除环境变量授权。
- MCP 的工具映射和请求头移到高级设置。停用或删除连接前会展示受影响能力。
- 需求链接模板支持 `{code}`，可输入编号预览，不自动访问或回写外部需求。

## 维护边界

操作日志只读取最近 300 条；项目/操作人/详情、动作和日期筛选仅作用于这批记录。日期筛选使用日志 UTC 日期。全量历史分页与备份恢复未纳入本次实现。

回收站沿用已有恢复规则、筛选及冲突提示。移除已注册工作区只取消注册，不删除本机目录。

软件更新操作针对 Flowlark 软件目录，与工作区 Git 同步不同。必须成功检测远端后才允许更新；本地改动、检测失败及缺少上游均不能显示为更新成功。更新完成后需重启服务。
