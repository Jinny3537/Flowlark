# 项目库表格与项目编辑设计

## 背景

当前项目库使用卡片展示项目名称、目录标识、基线状态、描述、版本数和更新时间，但项目字段较少，也没有编辑入口。参考目标表单后，需要将项目库改为适合多字段阅读的表格，并支持维护项目全名、业务代码、描述、优先级和归档状态。

项目概览还需要展示需求数、逾期数和版本数。Flowlark 当前需求没有截止日期，因此本次同时为需求增加截止日期，并建立可复用、可测试的逾期统计口径。

## 目标

- 将项目库从卡片改为多字段表格。
- 支持新建和编辑项目的完整字段。
- 允许修改项目业务代码，同时保持项目目录和历史链接稳定。
- 为需求增加截止日期，并在项目列表实时汇总需求数和逾期数。
- 保持旧项目、旧需求及现有 CLI/API 调用兼容。

## 非目标

- 不迁移或重命名项目目录。
- 不修改项目 `slug`、历史版本路径或已有外部链接。
- 不自动生成、迁移或重写需求编号。
- 不持久化项目统计值，也不引入额外数据库或缓存层。
- 不增加批量编辑、批量归档或项目删除能力。

## 数据模型

### 项目

`project.json` 新增以下可选字段：

- `priority`: 空字符串或 `P0`、`P1`、`P2`、`P3`。
- `archived`: 布尔值，缺失时按 `false` 处理。

现有 `code` 由创建时使用的标识扩展为可编辑的业务代码。`slug` 仍是项目的稳定存储和路由标识，编辑 `code` 不修改 `slug`。

新建项目或实际修改 `code` 时，代码必须满足以下规则：

- 1–40 位。
- 仅包含大写英文字母和数字。
- 与其他项目的业务代码不重复，比较时忽略大小写。

为兼容历史数据，已有小写或含连字符的代码在未被修改时不会阻止其他项目字段保存。

项目序列化顺序扩展为：

`slug`、`name`、`code`、`description`、`priority`、`archived`、创建信息、更新信息。

### 需求

`requirement.json` 新增可选字段：

- `dueDate`: 空字符串或合法的 `YYYY-MM-DD` 日期。

创建、编辑和外部同步均保持对缺失字段的兼容。外部数据未提供截止日期时，不覆盖已有本地截止日期。

需求序列化顺序在 `owner` 后加入 `dueDate`，保证 Git diff 稳定。

## 派生统计与业务规则

### 项目需求归属

一个需求归属于某项目，只要满足以下任一条件：

1. 需求的 `project` 与项目 `slug`、`code` 或 `name` 精确匹配；字符串比较忽略首尾空白，代码比较忽略大小写。
2. 需求已关联该项目下的任一版本。

同一需求即使同时满足多个条件，也只按需求编号计数一次。跨项目需求可以分别计入它实际匹配或关联的多个项目。

### 逾期规则

需求同时满足以下条件时计为逾期：

- `dueDate` 早于服务器本地日历中的今天。
- 需求派生状态不是 `delivered`。

今天到期不算逾期，从次日开始计入。没有截止日期的需求不计逾期。使用日期字符串按日比较，避免时分秒和 UTC 转换造成边界偏差。

### 项目列表返回值

`Hub.listProjects()` 和 `Hub.getProject()` 在读取项目时实时派生：

- `versionCount`
- `requirementCount`
- `overdueCount`

统计值不写入 `project.json`，避免需求同步、手工文件修改或 Git 合并后出现计数不一致。

## 后端与 API 设计

### 创建项目

`POST /api/projects` 接受：

- `name`
- `code`
- `description`
- `priority`
- `archived`

创建时继续由 `code` 生成小写 `slug`。业务代码保留用户输入的大写形式。

### 编辑项目

`PUT /api/projects/:slug` 接受同一组项目业务字段。服务端读取原项目后执行局部更新：

- `name` 不得为空。
- `code` 只有实际变化时才应用新格式和唯一性校验。
- `priority` 只接受允许的枚举值。
- `archived` 规范化为布尔值。
- 保存后更新 `updatedAt`、`updatedBy` 并写入 `PROJECT_UPDATE` 操作日志。

任一校验失败时不写入部分数据。

### 创建与编辑需求

需求创建、编辑接口接受 `dueDate`。服务层校验日期后再写入；空值规范化为空字符串。需求详情和列表沿用现有接口返回该字段，并额外返回可直接展示的派生状态。

## 前端设计

### 项目库表格

项目页使用 Ant Design `Table`，列顺序如下：

1. **项目**：项目全名作为可访问的详情链接，下一行显示业务代码。
2. **项目描述**：空值显示“暂无描述”，长文本省略并保留完整提示。
3. **项目概览**：同一单元格显示“X 条需求 · X 条逾期 · X 个版本”；逾期数大于零时使用危险语义文字标签，不能只用颜色。
4. **优先级**：显示 P0–P3 标签；空值显示“未设置”。
5. **状态**：显示“进行中”或“已归档”的文字标签。
6. **更新时间**：沿用统一时间格式。
7. **操作**：提供“查看”和“编辑”文字按钮。

页面顶部保留“新建项目”，并增加：

- 名称、代码和描述关键词搜索。
- 优先级筛选。
- 归档状态筛选，默认展示全部项目。

表格使用稳定的 `slug` 作为行键。窄屏按项目设计系统使用横向滚动，保证字段可读，不把桌面多列表格硬压成狭窄单元格。

### 项目表单

新建与编辑复用同一个项目表单组件或同一组字段定义，避免校验规则漂移。

字段顺序为：

1. 项目全名（必填）
2. 项目代码（必填）
3. 项目概览（仅编辑时只读展示）
4. 项目描述
5. 项目优先级
6. 已归档

项目代码下方显示说明：代码修改不会改变项目路径、历史版本或已有需求编号。历史非标准代码未修改时允许保存其他字段。

打开编辑弹窗时完整回填字段。取消后重置表单；保存成功后关闭弹窗、刷新列表并显示成功消息；保存失败时保留弹窗和用户输入，并显示明确错误。

在只读工作区中，新建和编辑入口均禁用。

### 需求截止日期

需求页面做以下同步调整：

- 新建需求表单增加截止日期选择器。
- 需求列表增加“截止日期”列；逾期项同时显示“已逾期”文字标签。
- 需求详情摘要增加截止日期。
- 编辑需求表单回填并允许修改或清空截止日期。

日期选择器在提交时转为 `YYYY-MM-DD`，读取时由同一格式创建日期值。截止日期的显示不附加时区或具体时间。

## 交互与无障碍

- 项目名称使用链接或语义按钮，不把整行做成只能鼠标点击的容器。
- 编辑按钮使用 Ant Design 图标时同时保留文字或提供可读标签。
- 表单控件均有可见标签，校验错误显示在对应字段附近。
- 弹窗沿用 Ant Design 焦点管理，关闭后将焦点返回触发按钮。
- 保存期间显示加载状态并防止重复提交。
- 保存成功显示消息提示；失败不静默。
- 状态、优先级和逾期信息均使用文字，不只依赖颜色。

## 错误处理

- 项目代码格式错误、代码重复、名称为空、优先级非法时，服务端返回明确业务错误。
- 截止日期格式或实际日期非法时拒绝保存，例如 `2026-02-30`。
- 前端捕获创建和更新错误，使用统一错误解析显示消息。
- 列表统计遇到旧数据缺字段时使用兼容默认值，不因单条旧数据使整个列表失败。

## 测试与验收

### 核心与 API 测试

- 新项目保存 `priority`、`archived` 和大写业务代码。
- 编辑项目能更新所有业务字段，但 `slug` 和项目目录不变。
- 编辑为重复或非法代码被拒绝，原文件保持不变。
- 历史非标准代码未修改时可保存描述、优先级或归档状态。
- 需求能创建、更新和清空合法截止日期，非法日期被拒绝。
- 项目需求数按编号去重，并支持字段匹配和版本关联两种归属方式。
- 昨日到期且未交付的需求计为逾期。
- 今日到期、未来到期、无截止日期或已交付的需求不计逾期。
- 旧项目和旧需求缺少新增字段时返回兼容默认值。

### 前端验证

- 项目库显示所有目标列，搜索与筛选结果正确。
- “查看”进入原项目路由，“编辑”不触发导航。
- 编辑弹窗正确回填、校验、保存和刷新。
- 创建与编辑需求能正确提交和回填截止日期。
- 需求列表和详情的截止日期、逾期状态一致。
- 只读工作区不可创建或编辑。
- 窄屏表格可访问且不撑破页面。
- 前端构建和现有测试通过。
