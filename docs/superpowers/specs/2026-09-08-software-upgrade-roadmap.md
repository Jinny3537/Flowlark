# Flowlark 软件升级规划（0.7.5 → 0.8.0）

日期：2026-09-08。状态：建议稿，版本号表示建议批次，不构成发布日期承诺。

## 最新调整：优先增加团队协作与角色模式

用户已明确将团队协作加入当前升级范围。下一批优先规划团队模式，原下文 0.7.6 起的回写、快照、运维等批次保留为后续候选，版本归属与排期重新确认，不再直接按旧表执行。

详见 [团队协作与角色模式方案](2026-09-08-team-collaboration-roles.md)。已确认：产品独立部署并通过 Git 同步；其他角色访问统一主机；无需登录，远程首次仅可选择游客、研发或测试，之后仅主机可以改角；使用浏览器访客标识记忆角色，IP 仅辅助展示；游客可直接浏览全部项目、评论和下载。同步策略、访客重置与细项操作权限继续细化。

## 目标与判断

沿用现有产品定位：外部需求池负责需求主数据，Flowlark 负责原型版本、迭代组织、交付快照和验收证据。推荐先收尾 0.7.5，再依次完善受控回写、需求变化处理、团队接入和真实试用。

本规划基于当前工作区 ff299dd 的静态检查和仓库验收记录。未重新运行应用、测试、构建或真实平台联调，未核实远端发布情况。团队人力、上线期限、回写字段权限尚未确定，因此按验收关口排序，不给出虚构工期。

## 下一批具体任务

1. **发布事实核对（发布负责人）**：建立包版本、提交、标签、安装包、验收证据对照，修正文档漂移。涉及 README.md、CHANGELOG.md、docs/UPDATES.md 和旧路线图。
2. **确认写回合同（产品负责人、平台负责人）**：逐字段记录来源、方向、允许动作、前置状态、失败处理。候选字段是交付版本、交付状态和证据链接；这些是待确认提案，不是平台现有合同。
3. **实现最小回写链路（集成研发）**：先选一个已批准字段，完成“预览差异 → 人工确认 → 执行 → 回读 → 显示结果”。优先复用 src/core/milestone-sync*.js、sync-policy.js、sync-queue.js 及 SyncCenter，不扩大到全字段。
4. **覆盖异常与恢复（研发、测试）**：模拟远端已成功但本地超时、权限失效、计划过期、重复请求、进程中断；结果未知时必须能核对远端事实，不能盲目重发。
5. **真实场景签收（产品、测试）**：在获授权的测试项目完成一次真实回写和一次故障恢复，记录提交、平台版本、输入条件及结果。真实平台操作另行执行，本规划不发送通知或修改远端数据。

建议每批只承诺一个主成果。具体人员与排期待团队容量明确后填写。

## 架构与取舍

继续使用 React/Ant Design 工作台、Node/Hono 服务、纯文本与 Git 存储。现有结构已承载主要闭环；此次静态证据不足以支持重写或引入数据库。收益是减少迁移与维护成本；代价是多人并发写入、常驻后台执行和集中权限仍受本地运行模式限制。

可信备选是暂时维持只读接入，提前完成 0.7.7 的变化提醒：实现更快、平台权限依赖更少，但交付结果仍需人工同步。若业务目标变为多用户同时在线编辑、集中权限或全天候自动执行，应另立服务端架构项目，重新评估存储与并发，不把这些能力塞进本轮升级。

本轮不新增云供应商；成本主要来自平台适配、回归和运维支持。平台许可/API 费用未核实，不承诺零成本。
