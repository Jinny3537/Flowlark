# 版本索引仅保留搜索框设计

## 目标

精简项目版本索引工具栏，只保留文本搜索框。删除生命周期状态筛选、版本排序、“显示已废弃版本”和高级筛选入口，避免低频控制项占用索引空间。

完成后，版本列表继续支持按版本号、标题、标签和关联需求进行文本搜索，并固定按最新版本优先展示；页面默认不加载已废弃版本。

## 范围

### 删除

- 版本索引中的生命周期状态下拉框。
- 版本索引中的新旧排序下拉框。
- 版本索引和空状态中的“显示已废弃版本”复选框。
- “高级筛选”入口，以及创建人、关联需求和外部依赖筛选面板。
- `ProjectVersions` 页面中仅服务于上述控件的 React 状态、动态状态选项、URL 参数同步、个人偏好同步和图标引用。
- 删除控件后不再使用的 `.indexFilters`、`.indexOptions` 和 `.advancedFilters` 样式。

### 保留

- 版本索引文本搜索框及其现有匹配字段。
- 版本列表默认的“最新优先”顺序。
- 版本卡片中的生命周期、评审和基线信息。
- `projectVersionsModel` 的通用过滤与排序能力，因为版本延续判断等页面逻辑仍使用默认排序。
- 服务端版本、评审、基线和个人偏好数据结构。

## 页面行为

版本索引工具栏只渲染搜索框。搜索词变化后，本地过滤当前已加载的非废弃版本；列表结果仍按默认“最新优先”顺序排列。

页面加载版本时不再传入 `includeVoid`，使用接口默认行为排除已废弃版本。无版本时只展示空状态说明和“创建首个版本”按钮，不再提供已废弃版本恢复入口。

## 状态与数据流

`ProjectVersions` 只保留 `query` 搜索状态。初始化时可以继续从项目筛选状态中读取搜索词，但不再恢复状态、排序、创建人、关联需求、外部依赖和已废弃版本选项。

URL 与个人偏好只同步搜索词。旧 URL 或旧个人偏好中的其他筛选字段不会影响列表，并在页面后续同步时自然清除，无需数据迁移。

调用 `filterVersions` 时只传入 `query`，由模型默认值维持最新优先排序。底层模型接口和测试保留，避免扩大本次变更范围。

## 错误与兼容处理

- 旧筛选参数不会触发报错，只会被页面忽略。
- API 加载和搜索错误处理保持现状。
- 已废弃版本仍保留在服务端，本次变更只移除该页面的查看入口。

## 验证

- 运行 `node --test web/src/pages/projectVersionsModel.test.js`，确认搜索和默认排序能力无回归。
- 运行 `npm run build --prefix web`，确认移除状态、引用和样式后前端生产构建通过。
- 页面验收确认版本索引只显示搜索框，空状态不再显示“显示已废弃版本”，搜索结果保持最新优先。

## 非目标

- 不删除或迁移服务端已废弃版本。
- 不修改版本卡片、版本详情、评审或基线功能。
- 不删除底层通用过滤模型或改动其他页面。
- 不进行无关样式调整或组件重构。
