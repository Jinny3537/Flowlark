# 移除项目版本任务筛选设计

## 目标

从项目版本索引中移除“全部 / 待评审 / 有疑问 / 基线历史 / 已废弃”任务筛选按钮，并完整删除这一筛选维度对应的前端状态、URL 参数、个人偏好、模型逻辑、样式和测试。

完成后，版本索引继续支持文本搜索、生命周期状态筛选、排序、高级筛选和“显示已废弃版本”；版本数据、评审状态与服务端接口不变。

## 范围

### 删除

- `ProjectVersions` 中的任务筛选按钮组。
- `taskFilter` React 状态，以及初始化、URL 同步、个人偏好保存和清除筛选中的相关处理。
- `projectVersionsModel` 中的任务值白名单、任务匹配函数、`filterVersions` 的 `task` 条件，以及 `projectFilterState` / `projectFilterQuery` 对 `task` 的解析和序列化。
- 任务筛选按钮专用 CSS。
- 验证任务筛选和 `task` 查询参数的测试断言。

### 保留

- 生命周期状态下拉框，包括“全部状态”及当前版本列表中的生命周期选项。
- 文本搜索、排序、创建人、关联需求、外部依赖和显示已废弃版本等筛选能力。
- 顶部“待评审 / 有疑问”数量，改为只读状态提示，不再触发版本过滤。
- 顶部“待归档”入口及其原有跳转行为。
- 版本评审状态、基线历史抽屉和相关服务端能力。

## 交互行为

版本索引在搜索框后直接显示生命周期状态与排序控件，不再出现任务筛选按钮行。

顶部规划摘要中，“待评审 / 有疑问”继续帮助用户了解项目状态，但以不可点击标签呈现；“待归档”仍是可点击入口并跳转到草稿箱。旧链接或个人偏好中携带的 `task` 字段将被忽略，并在页面下一次同步查询参数或保存偏好时自然移除。

## 数据流

版本列表只按以下本地条件过滤和排序：

1. 文本搜索。
2. 生命周期状态。
3. 创建人。
4. 关联需求。
5. 是否包含外部依赖。
6. 新旧排序。

`task` 不再参与页面状态、查询参数或偏好对象。此变更不修改服务端版本数据，也不增加迁移步骤。

## 错误与兼容处理

- 旧 URL 中的 `task` 参数不会导致报错，只会被忽略。
- 旧个人偏好中的 `task` 字段不会恢复筛选，也不会阻塞其他偏好的读取。
- “显示已废弃版本”仍决定请求是否包含已废弃版本；它与被删除的“已废弃”任务筛选不再联动。

## 验证

- 模型单元测试确认文本、生命周期和高级筛选仍正常，并确认生成的查询参数不再包含 `task`。
- 前端生产构建通过，确保移除状态与样式后没有残留引用或类型错误。
- 页面验收确认任务筛选按钮行消失，生命周期筛选、排序、只读统计标签和待归档跳转仍正常。

## 非目标

- 不删除评审状态或基线历史能力。
- 不改变版本卡片上的生命周期与评审标签。
- 不调整 API、持久化数据结构或后端规则。
- 不重构其他页面或筛选组件。
