# 左侧菜单折叠设计

## 背景与目标

Flowlark 桌面端左侧菜单固定占用 240px。用户希望在需要更大内容空间时收起菜单，同时继续快速访问各导航入口。

本次实现桌面端侧栏的展开与折叠，并记住用户最后一次选择。移动端继续使用现有抽屉导航，不改变路由、菜单顺序、选中态或业务功能。

## 方案比较

### 方案 A：保留图标栏（采用）

使用 Ant Design `Sider` 的受控 `collapsed` 状态，将侧栏从 240px 折叠到 72px。折叠后保留品牌图标和全部菜单图标，菜单名称通过 Tooltip 提示。

优点是用户仍可一键导航，空间释放明显，也能复用现有组件的折叠布局能力。缺点是仍占用少量横向空间。

### 方案 B：完全隐藏

折叠后侧栏宽度归零，只在页头保留展开按钮。它释放的空间最多，但每次切换导航都需要先展开菜单，操作成本更高。

### 方案 C：紧凑文字栏

折叠后保留约 136px 宽度和短菜单名称。识别成本低，但节省的空间有限，且需要维护另一套菜单文案。

## 交互设计

- 桌面端在侧栏与主内容相邻位置提供语义化折叠按钮。
- 展开状态按钮使用向左图标，`aria-label` 为“折叠菜单”；折叠状态使用向右图标，`aria-label` 为“展开菜单”。
- 折叠时侧栏宽度为 72px，只显示品牌图标和菜单图标；导航名称通过 Ant Design 菜单的折叠 Tooltip 展示。
- 底部服务状态在折叠时只保留状态圆点，并用 Tooltip 展示完整状态。
- 展开时恢复现有品牌名称、工作区名称、菜单文字和完整服务状态。
- 折叠与展开使用现有 200ms 过渡 token；系统启用减少动态效果时，沿用全局降级规则。

## 状态与数据流

折叠状态只属于当前浏览器 UI 偏好，不进入服务端或项目数据。

1. `AppShell` 初始化时从 `localStorage` 读取布尔偏好；缺失或无效值默认为展开。
2. 用户点击折叠按钮后更新 React 状态，并同步写入 `localStorage`。
3. 页面路由变化不重置折叠状态。
4. 窄屏切换到移动端时忽略桌面折叠状态；回到桌面端时恢复此前状态。

为避免组件测试依赖浏览器环境，偏好值的解析提取为小型纯函数并单独测试。`localStorage` 不可用时仍允许本次会话内切换，不向用户展示无意义错误。

## 组件与样式范围

- `web/src/components/AppShell.tsx`
  - 增加受控折叠状态和持久化。
  - 配置 `Sider` 的 `collapsedWidth`、`collapsed` 与自定义触发器。
  - 根据状态调整品牌、副文本和底部服务状态。
- `web/src/components/appShellModel.js`
  - 提供纯函数解析持久化偏好。
- `web/src/components/appShellModel.test.js`
  - 覆盖有效值、缺失值和无效值。
- `web/src/styles/global.css`
  - 补充折叠按钮、折叠品牌和状态区域样式。

不修改后端、路由、导航结构、移动端抽屉或其他页面。

## 异常与兼容

- 读取到未知持久化值时回退为展开状态。
- 浏览器禁止访问 `localStorage` 时捕获异常，只影响跨刷新记忆，不影响折叠交互。
- 768px 以下仍以现有移动端抽屉为准，不渲染桌面侧栏触发器。
- 折叠状态不隐藏图标、当前选中态或键盘焦点。

## 验收标准

- 桌面端可在 240px 展开态和 72px 图标栏之间切换，主内容区同步填充可用空间。
- 折叠态可通过图标和 Tooltip 访问全部导航，当前菜单选中态保持正确。
- 刷新页面后恢复最后一次桌面折叠状态。
- 展开、折叠按钮具有正确的 Tooltip、`aria-label` 和 `aria-expanded`。
- 移动端抽屉导航行为不变。
- 偏好解析测试、前端生产构建和全量 Node 测试通过。
- 浏览器中验证折叠、刷新恢复、导航跳转和移动端抽屉，无控制台错误或横向溢出。
