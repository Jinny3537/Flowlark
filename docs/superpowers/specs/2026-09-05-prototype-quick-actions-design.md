# 原型预览快捷操作优化设计

## 背景

版本工作台将“复制预览直链”“新窗口打开”“下载原型”收纳在页头的更多菜单中。这三个动作使用频率高，但必须先发现并打开菜单，操作层级过深。

## 目标与成功标准

- 将三个动作提升为一键可达的常驻按钮。
- 让动作出现在其作用对象“原型预览”附近。
- 窄屏下允许工具栏自然换行，不产生页面横向溢出。
- 保持复制反馈、新窗口安全参数和下载地址等现有行为不变。
- Web 生产构建通过，历史、并排对比、编辑和基线操作不受影响。

## 方案

采用已确认的“放进原型预览工具栏”方案。

在 `PrototypeStage` 的操作区增加三个带图标与文字的常驻按钮，顺序为：

1. 复制预览直链。
2. 新窗口打开。
3. 下载原型。

从 `VersionWorkbench` 页头删除原有更多菜单。历史、并排对比和基线按钮的位置、权限与行为不变。

## 组件边界与数据流

- `VersionWorkbench` 继续持有预览 URL、项目标识、版本号和消息反馈，并负责执行三个动作。
- `PrototypeStage` 只展示按钮，通过三个回调通知父组件，不读取路由参数、不拼接下载地址，也不直接调用 API。
- 复制继续复用现有 `copyPreviewLink`；打开与下载使用父组件传入的回调执行现有逻辑。

该边界保持展示组件简单，也避免把页面级地址和反馈逻辑复制到子组件。

## 响应式与无障碍

- 按钮使用 Ant Design `Button` 与 `@ant-design/icons`，不新增依赖。
- 三个按钮保留可见文字，不改成仅图标入口。
- 原型工具栏现有 `flex-wrap` 负责窄屏换行；移动端继续沿用至少 44 像素的按钮高度规则。
- 按钮使用原生按钮语义；新窗口继续使用 `noopener,noreferrer`。

## 错误处理

- 复制成功或失败继续显示现有消息提示。
- 新窗口与下载保持当前浏览器行为，不增加与本次需求无关的状态或异常处理。

## 修改范围

- `web/src/pages/VersionWorkbench.tsx`：删除更多菜单及相关图标和组件导入；向预览组件传递三个动作回调。
- `web/src/pages/workbench/PrototypeStage.tsx`：增加回调属性与三个常驻按钮。

不修改服务端接口、路由、持久化数据、全局样式或其他页面。

## 验证

- 运行 `npm run build --prefix web`。
- 检查页头不再包含“更多版本操作”菜单。
- 检查原型预览工具栏包含三个按钮，且分别连接到原有复制、打开和下载逻辑。
- 按用户要求，不进行浏览器人工验证。
