# Flowlark React 全量等价迁移与旧框架清理设计

## 背景

Flowlark 浏览器工作台的生产入口已经切换为 `web/src/main.tsx`，构建工具也只启用了 React 插件，运行依赖已改为 React 19、React Router 7 和 Ant Design 6。仓库内仍保留完整的 Vue 3、Vue Router、Pinia、Arco Design Vue 页面、组件、入口、API、状态和样式实现，因此当前代码处于“React 运行、Vue 成体系残留”的双栈状态。

审计基线如下：

- `web/index.html` 已挂载 `#root` 并加载 `main.tsx`。
- `web/vite.config.js` 已使用 `@vitejs/plugin-react`。
- `web/package.json` 已不再声明 Vue、Pinia 或 Arco 依赖。
- `web/src` 仍有 33 个 `.vue` 文件，以及旧 `main.js`、`router.js`、`store.js`、`api.js`、`style.css` 等文件。
- 旧 Vue 源码引用 106 个 API 能力，当前 React 界面引用 65 个；其中仍包含不可达孤立代码，必须先完成行为与可达性核对，不能直接按数量判断或删除。
- 当前生产构建成功；根测试基线为 268 项通过、0 项失败。
- 工作区已有大量未提交和未跟踪的 React 迁移成果。本设计把这些文件视为用户现有成果，实施时不得覆盖、回滚或用宽泛暂存命令误提交。

## 目标

1. 所有当前可达的浏览器工作台功能均由 React 原生实现。
2. 保留现有 React + Ant Design 工作台视觉，不复刻旧 Vue/Arco 外观。
3. 补齐旧 Vue 可达工作流中尚未进入 React 的业务能力、异常状态和恢复路径。
4. 删除所有不再需要的 Vue、Pinia、Arco 和 Umi 兼容代码、入口、依赖与文档声明。
5. 保持 Node 后端、HTTP API、仓库存储格式、原型 HTML 数据和预览 iframe 安全边界不变。
6. 通过功能矩阵、自动化测试、生产构建和桌面/移动端回归证明迁移等价。

## 非目标

- 不迁移未接入路由、入口或当前工作流的 Vue 孤立实现。
- 不恢复 `SetupWizard.vue` 或只由它使用的 `draftVersion` 界面流程。
- 不引入 Redux、Umi、第二套组件库或新的全局状态框架。
- 不改变后端 API、文件格式、CLI 行为或原型预览的跨源隔离。
- 不在本轮处理 Ant Design 主包导致的约 1.6 MB 构建体积警告。
- 不批量改写历史设计稿和历史实施计划中的技术栈记录；这些文件保留当时语境。

## 已选方案

采用按工作流逐组补齐的垂直迁移方式。先建立 Vue 到 React 的功能矩阵，再按“应用外壳与 Git → 项目与版本 → 搜索与需求 → 迭代、交付、草稿箱与回收站 → 设置与集成 → 全局清理”推进。每组完成实现、局部测试和构建验证后再进入下一组，所有组通过后统一删除旧框架。

未采用以下方案：

- 一次性补齐所有页面：修改面过大，回归难定位，也容易覆盖现有未提交成果。
- 长期保留双栈兼容：会继续维护两套路由、状态、API 和样式，违反全面清理目标。

## 目标架构

### 单一运行栈

- React 19 负责全部页面和组件渲染。
- React Router 7 负责全部工作台路由。
- Ant Design 6 和 `@ant-design/icons` 是唯一组件与图标体系。
- Vite 5 负责开发和生产构建。
- `web/src/main.tsx` 是唯一工作台入口。
- `web/src/services/api.ts` 是唯一浏览器 HTTP 请求层。

### 代码边界

- `main.tsx` 只包含应用 Provider、路由声明和顶层主题配置。
- `components/` 放置跨页面复用的 React 组件与应用外壳。
- `pages/` 放置路由级业务编排和相邻的特定组件、模型、样式。
- `services/api.ts` 负责传输、响应解析和结构化错误，不持有页面状态。
- `utils/` 和页面模型文件只放确定性纯逻辑，便于使用 Node 内置测试运行器验证。
- `styles/global.css` 和现有 CSS Modules 是唯一生效样式来源。

不为迁移重排所有现有 React 文件。只有在补齐功能时确实需要共享边界，才新增聚焦组件或纯逻辑模块。

### 跨页面运行状态

应用外壳在启动时加载健康状态、写权限、当前工作区和外壳级摘要，通过轻量 React Context 暴露给页面。页面业务列表、筛选、表单和详情仍使用本地 hooks，不引入第三方状态库。

服务端权限始终是最终闸门。React 根据运行状态提前禁用或隐藏写操作，但必须正确显示服务端返回的只读拒绝。

### 路由统一

所有页面直接使用 `react-router-dom` 的导航和参数 API。删除 `@umijs/max` 别名、`umi-shim.ts` 和 `window.location.hash` 兼容导航。保留已有业务路径，并恢复 `/oplog` 到 `/settings/oplog` 的兼容跳转。

- Git 改动摘要与面向协作/AI 的说明。
- 同步完成后的外壳状态刷新。

### 2. 项目与版本

保留现有 React 项目列表、版本时间线、对比页和版本工作台，补齐并验证：

- 版本导入时的变更影响建议。

- 版本对版本、原型对系统的比较和 URL 状态恢复。

现有 React 工作台与对比实现以验证和修复遗漏为主，不重新设计。

### 3. 搜索与需求

补齐：

- 当前工作区和全部已注册工作区搜索。
- 项目、需求、迭代等结构化筛选。
- 已存视图读取、应用和保存。
- 跨工作区结果的来源说明与安全跳转行为。
- 需求创建、详情编辑和导出。
- 外部需求提供方的凭据保存、搜索、导入和同步。

### 4. 迭代、交付、草稿箱与回收站

补齐：

- 迭代创建、条目添加/移除、详情更新和导出。
- 单个迭代同步、创建后同步和批量同步。
- 创建不可变交付快照和查看通知队列。
- 通知 Webhook 配置、测试和失败重试。
- 草稿箱失败项重新归档。
- 回收站版本恢复。

### 5. 设置与集成

补齐：

- 工作区注册、克隆、移除和跨仓库索引构建。
- Git 远端和局域网设置。
- MCP 服务配置、密钥设置/删除、能力映射、测试和移除。
- 软件更新状态检查和安全拉取。
- 操作日志查看。
- 现有配置 schema 分组、恢复默认值、重启提示和只读保护。

### 6. 明确删除的孤立功能

以下内容不迁移：

- 未进入 Vue 路由表的 `SetupWizard.vue`。
- 仅由该向导调用的 `draftVersion` 界面流程。
- 没有生产入口、路由或当前 React 消费者的重复旧组件和辅助模块。

删除前仍需通过引用审计确认它们确实不可达。

## 视觉与交互一致性

- 保留已确认的柔和均衡 React 工作台视觉。
- 统一使用 `PageHeader`、`State`、Ant Design 表单、消息、确认弹窗和抽屉模式。
- 使用现有 `--fl-*` 设计 token，不建立平行 token 体系。
- 统一使用 `@ant-design/icons`，不用 emoji 充当功能图标。
- 状态同时包含文字与颜色，不依赖颜色单独传达含义。
- 写操作统一展示权限禁用、提交中状态和明确结果。
- 主要触控操作在移动端保持可用尺寸，页面在 390px 下不产生页面级横向滚动。
- `DESIGN.md` 和 `design-system/flowlark/MASTER.md` 更新为 React 19、Ant Design 6、React Router 7 和当前 token 来源。

## 数据流

### 查询

页面查询采用加载、成功/空、失败三态。加载失败在页面内显示稳定错误和重试入口。路由参数快速变化时，旧请求结果不得覆盖新页面；使用请求序号或取消标记忽略过期结果。

### 写入

所有写操作遵循同一顺序：

1. 前端校验必填项、格式、文件类型和大小。
2. 对删除、覆盖、回滚、冲突选择和更新等高影响操作显示确认。
3. 锁定提交控件，避免重复请求。
4. 调用现有 API。
5. 成功后显示明确反馈并只刷新受影响数据。
6. 失败时保留表单、抽屉、选择和用户输入，允许修正或重试。

### 状态映射

版本、评审、Git、同步和通知状态只保留一份 React 映射。页面不得各自复制不同文案或颜色。旧 `web/src/ui/status.js` 在 React 映射覆盖其语义后删除。

### 凭据

MCP、Webhook 和外部需求凭据只允许输入和覆盖，不从服务端回显明文。保存成功后清空输入。错误消息不得包含凭据值。

## 请求层与错误处理

`services/api.ts` 提供统一请求函数和结构化 `ApiError`，至少包含 HTTP 状态、业务错误码、消息和可选提示。请求层必须覆盖：

- 网络无法连接。
- 空响应。
- JSON 与文本响应。
- 非 JSON 错误响应。
- 带 `code/message/hint` 的业务错误。
- 局域网只读和 Git 只读拒绝。

请求层不直接依赖 React 组件或静态消息 API。页面加载错误进入 `State`；用户触发的操作错误通过 Ant Design `App` 上下文显示。所有异步事件处理器必须捕获失败，不能产生未处理 Promise。

## 迁移顺序与门禁

### 阶段 1：基础一致性

- 建立功能矩阵。
- 统一路由 API，删除 Umi 兼容层。
- 完善请求错误和共享状态映射。
- 建立跨页面运行状态 Context。

### 阶段 2：应用外壳与 Git

- 补齐外壳状态、快捷搜索和通知交互。
- 补齐完整 Git 诊断、初始化、冲突与同步流程。

### 阶段 3：项目与版本

- 补齐影响建议、回滚和恢复。
- 完成工作台与对比功能矩阵验证。

### 阶段 4：搜索、需求和迭代

- 补齐跨工作区搜索与已存视图。
- 补齐需求外部集成、编辑和导出。
- 补齐迭代维护、同步和导出。

### 阶段 5：交付与系统能力

- 补齐通知配置、草稿重试和回收站恢复。
- 补齐工作区、MCP、软件更新和操作日志。

### 阶段 6：旧框架删除

只有前五个阶段的功能矩阵、测试和构建全部通过，才删除：

- 所有 `.vue` 文件。
- `web/src/main.js`、`router.js`、`store.js`、`api.js`、`utils.js`、`style.css`。
- 旧 `ui/feedback.js`、`ui/status.js`、`brand.js` 和其他经引用审计确认无 React 消费者的辅助模块。
- `umi-shim.ts` 和 Vite 中的 `@umijs/max` 别名。
- 文档中仍指向现役 Vue/Arco 技术栈的描述。

每个阶段必须先通过局部测试与 `web` 生产构建。实施过程中只修改该阶段涉及的文件，不顺手重构相邻代码。

## 验证策略

### 功能矩阵

为每个旧 Vue 可达路由记录：

- 用户操作和入口。
- 对应 API。
- 正常、空、加载、只读和错误状态。
- React 页面或组件。
- 自动化或人工验证方式。

矩阵中没有 React 对应项的可达功能不得标记完成。未迁移项只能在证明不可达后归入删除清单。

### 自动化验证

- 运行根目录 `npm test`，保留现有后端、CLI 和 React 纯逻辑测试。
- 为请求错误、状态映射、筛选、序列化和迁移中新增的确定性规则补充 Node 单元测试。
- 运行 `cd web && npm run build`。
- 使用现有 Playwright 回归设施覆盖所有 React 路由和新增关键工作流。
- 检查浏览器控制台没有新增 React 错误和未处理 Promise。

### 页面验证

- 桌面基准：1280×900。
- 移动端基准：390×844。
- 必要时使用 1920px 宽屏检查内容最大宽度和布局拉伸。
- 检查页面级横向溢出、抽屉/弹窗遮挡、焦点可见、键盘操作、状态文字和加载占位。

### 最终静态检查

最终必须满足：

- `web/src` 不含 `.vue` 文件。
- 活跃源码、Vite 配置和 `web/package.json` 不含 Vue、Pinia、Arco 或 `@umijs/max` 引用。
- `web/index.html` 只加载 `main.tsx`。
- 活跃源码只有 `services/api.ts` 定义浏览器 API 客户端。
- README、`DESIGN.md` 和设计系统不再把 Vue/Arco 描述为当前技术栈。
- 生产构建、完整 Node 测试和 UI 回归全部通过。

## 工作区与提交安全

实施前后都必须检查 `git status --short`。现有修改和未跟踪 React 文件属于用户成果：

- 不使用 `git add .`、`git add -A` 或其他宽泛暂存命令。
- 不使用 reset、checkout 或清理命令回退用户改动。
- 每次只暂存当前阶段明确列出的文件，并检查暂存文件清单。
- 如果待修改文件包含无法区分来源的并发改动，先停止并说明冲突，不覆盖处理。

## 验收标准

1. 所有旧 Vue 可达功能在 React 中存在等价、可操作的实现。
2. 旧 Vue 不可达孤立功能已删除且没有被重新引入。
3. 所有工作台路由均由 React 渲染，不执行 Vue 入口或兼容跳转。
4. 旧框架源码、运行依赖、构建插件、兼容层和现役文档声明清零。
5. React 页面使用统一组件、状态、错误反馈、图标和设计 token。
6. 失败写入保留用户输入并提供可重试路径；只读与网络错误有清晰说明。
7. 原型预览继续使用独立端口和既有 sandbox 边界。
8. 1280px 桌面和 390px 移动端的主要工作流可用，无页面级横向滚动。
9. 根测试、React 纯逻辑测试、生产构建和 UI 回归全部通过。
10. 用户当前未提交改动均被保留，没有被迁移提交意外包含。
