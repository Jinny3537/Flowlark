# 项目页面布局优化设计

## 背景

项目列表和项目版本页已经具备项目编辑、版本浏览、需求统计与逾期统计能力，但当前信息层级存在三个问题：

- 项目列表中的描述字段容易被长文本占据，降低多项目扫描效率。
- “进行中”状态使用大面积灰绿色填充标签，不符合轻量状态标识规范。
- 项目版本页把项目代码和完整描述拼成正文，长描述会推高页头；无版本时又用超过 400px 的空白容器承载一个弱提示，主操作与内容关系不清晰。

本次只重组项目列表和项目版本页的呈现方式，不改变项目、版本、需求或基线的业务规则。

## 目标

- 提高项目列表的扫描效率，移除不可控长文本。
- 统一项目状态为标准圆点加文字的轻量表达。
- 把项目版本页改为清晰的“项目摘要—状态摘要—版本工作区”三层结构。
- 同时优化有版本、无版本、只读和窄屏状态。
- 保留现有版本选择、筛选、键盘操作、详情抽屉和新建版本流程。

## 非目标

- 不删除项目描述字段，也不移除编辑弹窗中的描述维护能力。
- 不修改项目、版本、基线和需求的存储结构或 API。
- 不重写版本详情、变更日志或关联需求的业务功能。
- 不新增图表、动画、批量操作或新的页面路由。
- 不更改 Flowlark 品牌色、字体或全局导航。

## 项目列表

### 列与搜索

项目列表移除“项目描述”列，保留以下列：

1. 项目：项目名称和项目代码。
2. 项目概览：需求数、逾期数和版本数。
3. 优先级。
4. 状态。
5. 更新时间。
6. 操作：查看、编辑。

搜索只匹配项目名称和项目代码。隐藏描述后不继续把描述作为搜索字段，避免出现用户无法从结果中解释的隐形命中。

项目编辑弹窗继续显示和保存项目描述。

### 状态规范

项目状态不再使用有背景填充的 `Tag`，改用 Ant Design `Badge` 的圆点加文字：

- 进行中：`success` 圆点 + “进行中”。
- 已归档：`default` 圆点 + “已归档”。

文字始终存在，颜色只作辅助。状态不可点击，不使用交互式标签外观。

## 项目版本页

### 第一层：项目摘要

页头保持返回入口和“项目版本”眉题，项目名称为主标题。项目描述不在此页展示。

标题下方使用紧凑元信息行展示：

- 项目代码。
- 项目优先级，未设置时不显示标签，只显示“未设置”。
- 版本总数。
- 当前基线；无基线时显示“未设置”。
- 最近更新时间。

右侧只保留“新建版本”主操作。只读时按钮禁用，沿用现有只读提示。

### 第二层：状态摘要

当项目存在版本时，在版本工作区上方展示紧凑状态摘要：

- 当前基线版本号与标题。
- 新版本数量；没有新版本时不占额外提示空间。
- 基线更新时间和维护人。
- “查看详情”“打开工作台”；存在可回滚基线且当前可写时显示“回滚上一版”。

沿用现有基线业务规则和确认流程。状态摘要使用浅主色背景和左侧主色边线，不拆成多个指标卡。

“显示已废弃”从全局页头移动到版本索引筛选区，因为它只影响版本列表。

### 第三层：版本工作区

有版本时继续使用主从布局：

- 左侧 320px 版本索引：搜索、状态筛选、排序、显示已废弃，以及可滚动版本列表。
- 右侧版本详情：状态、版本号、标题、创建信息、变更数、需求数、外部依赖、变更日志和关联需求。

保留以下现有行为：

- 上下方向键切换版本。
- 回车打开版本工作台。
- 选中项使用浅主色背景和左侧主色边线。
- 详情加载缓存、失败重试与移动端详情抽屉。
- 设置基线、回滚、标记已读、下载、废弃、恢复和删除流程。

## 无版本状态

无版本时不渲染高达 420px 的通用空白容器，改用约 260px 高的引导卡：

- 使用 `FileAddOutlined`。
- 标题：“还没有版本”。
- 说明：“创建首个版本后，可以在这里查看原型、变更和关联需求。”
- 主按钮：“创建首个版本”，直接打开现有 `NewVersionDialog`。

只读状态下主按钮禁用；页面上方的只读说明仍然保留。返回项目库已有独立入口，空状态不重复添加返回按钮。

## 响应式

- 1440px 与 1024px：保持 320px 版本索引和自适应详情区。
- 900px 以下：版本工作区切换为单列版本索引，选中版本通过全屏抽屉展示详情。
- 768px 以下：项目摘要元信息和操作自动换行，筛选控件改为单列。
- 390px：页面本身不得产生横向滚动；版本编号、状态和操作文字保持可读。

项目列表继续使用组件内部横向滚动，并保留固定操作列。移除描述列后调整表格滚动宽度，避免无意义的大段空白。

## 状态与异常

- 项目和版本加载失败继续显示结构化错误和重试按钮。
- 初次加载继续使用与目标结构一致的骨架屏。
- 筛选后无结果继续显示“没有匹配的版本”和“清除筛选”。
- 新建版本成功后继续选中新版本并刷新项目统计。
- 所有写操作继续受 `canWrite` 控制。

## 无障碍

- 状态圆点必须同时带文字。
- 新建版本、查看详情、打开工作台和更多操作使用语义按钮。
- 图标按钮保留可读 `aria-label`。
- 版本索引继续使用 `listbox` / `option` 与 `aria-selected`。
- 键盘焦点样式和抽屉焦点管理沿用现有实现。
- 关键状态和操作文字不得为压缩布局而被截断。

## 测试与验收

### 自动化

- 更新项目列表纯模型测试，确认描述不再参与搜索。
- 保持项目列表与版本筛选、排序和相邻版本测试通过。
- 前端生产构建通过。
- 全量 Node 测试通过。

### 浏览器验收

在 1440px、1024px、768px 和 390px 验证：

- 项目列表不存在描述列，名称/代码、概览、优先级、状态、更新时间和操作正常。
- 进行中与已归档使用圆点加文字，颜色和文字同时表达状态。
- 项目版本页不展示项目描述。
- 无版本状态高度适中，主操作明显且能打开新建版本弹窗。
- 有版本状态的项目摘要、基线摘要、版本索引和详情层级清晰。
- “显示已废弃”位于版本索引筛选区并正常生效。
- 移动端列表与详情抽屉正常，页面不产生横向溢出。
- 浏览器控制台和页面运行时错误为空。
