# Flowlark v0.7.5-v0.8.0 版本优化计划

日期：2026-09-05。定位已调整：优先集成独立需求池平台。

本文是建议路线图，供产品和研发评审；不是已实现能力或发布日期承诺。前提假设是：需求池平台已经独立存在，并且在本阶段作为需求主数据与协作入口；Flowlark 不重复建设完整需求池，而是负责接入、同步、发版验收、证据沉淀与下游交付闭环。

## 1. 目标与边界

到 v0.8.0，真实团队可以把独立需求池平台作为需求来源，在 Flowlark 中完成需求选择、版本组织、交付快照、验收证据和反馈追踪。Flowlark 与需求池平台之间的数据关系清晰、可追溯、可恢复，不因同步失败、权限变化或字段差异破坏需求主数据。普通用户优先通过导入平台 MCP 配置文件完成接入，本机 MCP 中心退为高级设置和诊断入口。

核心目标：

| 目标 | 说明 |
|---|---|
| 需求池平台为上游权威源 | 需求标题、业务描述、优先级、状态、负责人等主字段默认来自需求池平台 |
| Flowlark 管理交付过程 | 版本、迭代、发版快照、验收、交付证据和反馈处理仍由 Flowlark 组织 |
| 轻量配置入口 | v0.7.5 先支持导入配置 JSON；后续再支持本机 MCP 服务包和启动脚本 |
| 双向同步有限开放 | 先支持受控字段回写，不做全量双向覆盖 |
| 冲突可解释 | 字段映射、权限不足、远端变更、对象删除都必须显示原因和处理动作 |
| 不重复造平台 | 本阶段不建设完整需求池 UI、权限中心或通用工作流平台 |

本阶段不以“自动闭环”为第一主线。自动化仍保留，但服从需求池平台集成的可靠性要求：先确保需求来源、字段映射、状态同步和证据关联稳定，再扩大自动推进能力。

## 2. 当前判断

| 项目 | 当前判断 | 对规划的影响 |
|---|---|---|
| 发布基线 | 根目录和 Web 包版本仍为 0.7.0，后续变更列在 Unreleased | 后续版本按能力验收推进，不用版本号代替发布事实 |
| 既有需求能力 | 已有需求/迭代主导、绑定、冻结、同步中心等基础 | 可作为集成承载层，但需求主数据应让位于外部需求池 |
| v0.7.4 | 正在建设发版、验收、快照、反馈等交付能力 | 仍是集成后的交付闭环基础，不能跳过 |
| 外部绑定能力 | 已有受控外部绑定、托管字段、状态映射思路 | 需要改造成面向需求池平台的适配与资格验证 |
| MCP 配置体验 | 现有路径需要先到 MCP 中心创建服务、运行配置和能力映射，再回项目选择 | 对真实团队过重；v0.7.5 改为平台配置 JSON 导入优先 |
| 多人协作 | 仍主要依赖 Git 和本地文件 | 不承诺多设备同时自动写入，也不替代需求池平台的协作权限 |
| 真实平台信息 | 集成合同已落到 `docs/REQUIREMENT-POOL-MCP.md`、模板接口和 schema 接口；真实平台 manifest、凭据和字段语义仍未提供 | v0.7.5 的本地集成链路可以验证，真实平台验收仍必须单独执行 |

证据来自本次仓库上下文和既有规划文档。本路线图没有验证真实需求池平台接口，也没有重新运行测试。

## 3. 路线选择

| 路径 | 收益 | 代价 | 选择 |
|---|---|---|---|
| 先建立需求池平台集成契约，用配置 JSON 降低接入成本，再逐步扩展同步与交付闭环 | 每版都围绕真实上游平台产生可验收能力，普通用户不用手工理解 MCP 中心细节 | 需要尽早拿到配置文件样本、接口、字段和权限样本 | 推荐，本文采用 |
| 继续做 Flowlark 内建需求池，再后接外部平台 | 内部体验可控 | 与现有独立平台重复，后续迁移成本高 | 不采用 |
| 先做完整自动化闭环，再补需求池集成 | 自动化成果明显 | 主数据源未定时容易返工 | 不采用 |

相比上一版规划：v0.7.5 的主题从“受控自动闭环”改为“需求池平台最小集成”；v0.8.0 的稳定标准从“自动闭环可用”改为“需求池平台集成后真实团队可稳定交付”。

|---|---|---|---|---|---|

| v0.7.6 | 受控状态与字段回写 | 托管字段定义、状态映射、幂等回写、回读验证、失败暂停 | 批量回写预览、回写摘要 | Flowlark 交付动作能安全回写需求池指定字段，不覆盖非托管内容 | 核心研发；测试验证权限和冲突 |
| v0.7.7 | 需求变更与版本快照 | 远端变更检测、冻结后差异处理、版本快照绑定需求池版本、验收证据关联 | 变更影响报告 | 需求池变更不会静默污染已发版材料，用户能处理差异 | 核心研发；产品与测试共同验收 |

| v0.8.0 | 集成稳定版发布 | 冻结范围、最终回归、发布包与文档一致、已知限制清晰 | 无新增功能承诺 | 可交付受支持团队使用，支持矩阵和恢复路径明确 | 发布负责人；产品与研发共同签收 |

## 5. v0.7.5：需求池平台最小集成

v0.7.5 的目标不是把所有流程自动化，而是打通真实需求池平台到 Flowlark 的最短可用链路。默认入口是上传或选择平台提供的配置 JSON，由 Flowlark 解析出服务、工具、字段和能力草稿；本机 MCP 中心只作为高级入口保留。

必须先形成集成契约：

| 契约项 | 最低要求 |
|---|---|
| 身份与权限 | 明确使用个人授权、服务账号或项目级凭据；读取、回写、状态变更权限分开验证 |
| 需求唯一标识 | 保存需求池平台的稳定 ID、URL、更新时间和来源项目 |
| 字段模型 | 明确标题、描述、优先级、状态、负责人、验收口径、附件/链接的映射 |
| 状态模型 | 区分需求池状态、Flowlark 版本状态、交付状态和验收状态 |
| 分页与增量 | 支持按项目/空间拉取，记录同步游标或更新时间 |
| 错误语义 | 权限不足、字段缺失、对象删除、限流、网络错误必须可区分 |

配置 JSON 的最低内容：

| 配置项 | 最低要求 |
|---|---|
| manifestVersion | 配置文件版本，便于后续升级兼容 |
| platform | 平台名称、平台类型、文档 URL 和可选图标 |
| transport | HTTP/SSE 服务地址与超时；v0.7.5 不激活本机 stdio 服务包或上传的可执行文件 |
| tools | 需求搜索、需求详情、连接测试等工具名称和兼容参数约定 |
| fields | 平台字段与 Flowlark 字段的建议映射 |
| statuses | 平台状态与 Flowlark 交付状态的建议映射 |
| secrets | 需要用户单独填写的 token、密码或账号占位，不允许包含明文密钥 |
| safety | 只读/可写能力、危险操作声明、最小权限说明 |

P0 范围：

1. 新增“导入需求池 MCP 配置”入口，接受配置 JSON 文件并完成 schema 校验、能力识别和风险提示。
2. 从配置 JSON 生成连接草稿，包括平台地址、项目/空间标识、认证方式、工具映射和字段映射。
3. 要求用户单独填写敏感信息；token、密码、本机路径和个人账号不从配置文件导入到 Git 共享配置。
4. 支持从需求池平台拉取需求列表和详情，落地为 Flowlark 的外部需求引用。
5. 支持把拉取的需求加入版本或迭代范围，但不把外部需求强制复制成内部主数据。
6. 支持字段映射配置，未映射字段只展示原始引用，不参与自动判断。
7. 支持手动刷新单条需求和项目需求列表，显示新增、更新、删除或不可访问状态。
8. 发版快照中记录需求池来源 ID、URL、同步时间和关键字段摘要。

不做：

| 不做项 | 原因 |
|---|---|
| 自动创建需求池平台需求 | 上游平台已是需求入口，先避免反向写入造成重复 |
| 全量双向同步 | 字段语义和冲突规则未稳定前风险过高 |
| 自建完整需求池看板 | 与独立需求池平台重复 |
| 自动关闭需求 | 需要等 v0.7.6 明确托管字段和状态映射 |
| 安装或运行上传的 MCP 服务包 | v0.7.5 只支持配置 JSON；本机可执行文件和启动脚本放到后续版本验证 |
| 从上传文件导入明文密钥 | 密钥必须由用户在本机安全输入和保存 |

验收：在真实测试需求池项目中，通过配置 JSON 完成导入、预览、敏感信息补录、权限检查、需求拉取、详情展示、加入版本、生成快照。配置 JSON 缺字段、schema 不兼容、声明危险写操作、包含疑似明文密钥、断网、凭据失效、需求被删除、字段缺失时界面能明确显示状态，不能误报同步成功。

## 6. v0.7.6：受控状态与字段回写

v0.7.6 才开放有限写入。原则是只写托管字段，只按明确状态映射执行，所有写入都要有幂等标识、前后值记录和回读验证。

P0 范围：

1. 定义需求池平台托管字段，例如 Flowlark 版本号、交付状态、验收结论、最后同步时间、证据链接。
2. 建立状态映射表，明确哪些 Flowlark 动作可以触发需求池状态或字段变化。
3. 回写前展示影响范围和字段差异，默认人工确认；可信项目可在规则满足后自动执行。
4. 回写后回读验证，确认平台实际值与预期一致；不一致时暂停并要求人工处理。
5. 对重复触发使用同一逻辑操作 ID，避免重复追加评论、重复状态流转或重复证据链接。
6. 权限不足、状态不可流转、对象删除、字段被管理员修改时停止自动写入。

验收：完成一次从 Flowlark 发版/验收到需求池平台托管字段更新的闭环；覆盖重复点击、部分成功、权限撤销、远端字段变化和网络中断。非托管字段不得被覆盖。

## 7. v0.7.7：需求变更与版本快照

v0.7.7 处理真实团队最常见的问题：需求池里的需求在 Flowlark 组织版本后继续变化。

P0 范围：

1. 版本范围冻结后记录需求池关键字段摘要和远端更新时间。
2. 发版前重新检查需求池变化，识别标题、描述、优先级、验收标准、负责人和附件变化。
3. 将变化分为可接受更新、需要重新确认、阻断发版三类。
4. 验收记录绑定到具体发版快照，而不是绑定到需求池的最新状态。
5. 需求池状态变化不能自动改写历史快照；只能形成新的差异记录。
6. 删除或失去访问权限的需求必须保留历史引用和快照材料，不能从版本记录中消失。

验收：覆盖冻结后需求改名、验收标准变化、附件变化、远端删除、权限变化和重新发版。旧验收不能被错误套用到新快照。

## 8. v0.7.8：团队接入与运维

v0.7.8 的目标是让非开发角色也能接入和维护这条链路，并补齐“本机 MCP 服务包或启动脚本”的受控导入。配置 JSON 仍是推荐入口；服务包导入仅用于平台必须通过本机 stdio 服务运行的场景。

P0 范围：

1. 提供需求池平台支持矩阵，明确平台版本、API 能力、字段类型、状态流转限制和已知缺口。
2. 支持本机 MCP 服务包或启动脚本导入，但必须经过文件类型、来源说明、哈希校验、命令预览和用户确认。
3. 服务包导入只生成本机运行配置，不把可执行文件路径、账号、密码和 token 写入仓库配置。
4. 健康诊断展示连接状态、授权身份、项目范围、最后成功同步时间、待处理队列、失败原因和恢复入口。
5. 配置变更后重新验证资格，包括凭据、项目、字段映射、状态映射、托管字段和本机运行配置。
6. 提供升级、备份、恢复和重新授权文档。
7. 支持脱敏诊断材料导出，用于排查集成问题。

验收：产品或测试角色按文档完成一次配置 JSON 接入和一次本机 MCP 服务包接入，处理凭据过期、字段映射错误、权限不足、服务包哈希不匹配和升级恢复，无需直接编辑 JSON 或数据库文件。

## 9. v0.7.9：真实团队试用与 RC

试用目标是验证“独立需求池平台 + Flowlark 交付管理”在真实节奏下能稳定运转。

建议门槛：

| 维度 | 建议门槛 | 口径 |
|---|---|---|
| 业务覆盖 | 至少 1 个真实团队、2 个完整迭代、累计不少于 10 个工作日 | 覆盖新增需求、需求变更、发版、验收和反馈处理 |
| 集成稳定性 | 不少于 50 次需求池读取/刷新，读取成功率不低于 99% | 外部平台不可用单独记录，不计入 Flowlark 缺陷但要展示 |
| 写入安全 | 不少于 20 次托管字段回写，0 越权覆盖、0 重复写入副作用 | 普通多次更新与同一操作重复写入分别统计 |
| 差异处理 | 至少覆盖 5 类远端变化并形成正确处理结果 | 包括删除、权限变化、字段变化、状态变化、附件变化 |
| 恢复能力 | 至少一次重启恢复、一次断网恢复、一次备份恢复 | 已完成远端写入不被重复执行 |
| 性能 | 约定参考设备和样本上，常用列表/详情 P95 <= 2 秒 | 建议样本为 1,000 需求、100 迭代、10,000 条记录 |
| 发布阻断 | 无未解决 P0/P1 缺陷 | 此处为缺陷严重级别，区别于可延后的 P1 功能 |

未达到样本量则继续 RC。指标保留样本量、成功数、失败数、设备条件和外部平台状态，不能只统计成功请求。

## 10. v0.8.0：集成稳定版发布

v0.8.0 只纳入已通过 v0.7.5-v0.7.9 验收的需求池平台集成能力和必要阻断修复。发布包、CLI、Web、Schema、更新日志和启动器版本信息必须一致。

最终检查覆盖：

1. 全新安装后通过配置 JSON 连接需求池平台。
2. 需要本机 stdio 服务的平台可以通过服务包或启动脚本完成受控导入。
3. 从上一真实正式版本升级并保留既有 Flowlark 数据。
4. 需求池读取、刷新、字段映射、状态映射和托管字段回写。
5. 冻结后远端变更、删除、权限变化和重新发版。
6. 断网、进程退出、凭据过期、限流和备份恢复。
7. 只读用户、管理员、自动执行身份的权限边界。

发布后默认不启用自动写入；项目管理员显式配置托管字段和状态映射后才允许回写。若真实需求池平台联调或试用门槛未通过，继续 RC，不以版本号压过退出条件。

## 11. 依赖与执行顺序

主依赖顺序：确认需求池平台配置 JSON 契约 -> v0.7.5 最小读集成 -> v0.7.6 受控写回 -> v0.7.7 变更与快照 -> v0.7.8 服务包接入与运维 -> v0.7.9 试用 -> v0.8.0 发布。

| 依赖 | 需要时间 | 责任角色 | 未满足时处理 |
|---|---|---|---|
| 需求池平台 API 文档与测试环境 | v0.7.5 开发前 | 平台负责人、集成研发 | 只能做适配器骨架，不能通过真实验收 |
| 配置 JSON 样例与 schema | v0.7.5 导入向导开发前 | 平台负责人、集成研发 | Flowlark 已提供内置模板、JSON Schema 和 `docs/REQUIREMENT-POOL-MCP.md`；真实平台仍需提供可验收 manifest |
| 字段与状态语义确认 | v0.7.5 字段映射前 | 产品负责人、平台负责人 | 限制为只读引用，不开放写回 |
| 可写测试项目与限定权限凭据 | v0.7.6 回写前 | 团队管理员、集成负责人 | 继续只读集成，不开放托管字段 |
| v0.7.4 发版验收基础 | v0.7.7 快照和验收关联前 | 核心研发、测试 | 不能宣称交付闭环完成 |
| 本机 MCP 服务包、哈希和启动说明 | v0.7.8 服务包导入前 | 平台负责人、集成研发 | 保持配置 JSON 和手工高级配置路径 |
| 试用团队、样本和周期 | v0.7.8 结束前 | 产品负责人、试用团队 | 延长 RC |
| 发布与恢复验收签收 | v0.8.0 发布前 | 发布负责人、测试 | 暂不发布稳定版 |

建议每版只承诺一个主成果，预留约 20% 容量处理真实平台联调暴露的问题。人力不足时先减 P1 功能，保留该版 P0；新增需求必须明确替换项。

## 12. 本阶段不扩展的范围

- 重建独立需求池平台已有的需求管理、权限、看板和工作流能力。
- 多需求池平台同时作为主数据源。
- 上传任意文件后直接运行本机命令。
- 外部平台反向覆盖 Flowlark 历史快照、验收结论或发布证据。
- 未经映射确认的全量双向同步。
- AI 自动决定需求优先级、验收结论、豁免或反馈关闭。
- 常驻云端服务、自动选主、多设备同时自动写入和全天候运行保证。

以上取舍用于保证 v0.8.0 的集成质量，不代表永久不做。
