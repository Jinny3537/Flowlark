## 目标与取舍

将最多 12 个平铺入口收敛为 6 个任务导向入口，让用户能找到设置、完成配置、看到实际效果、处理失败。先整合重复入口和修复配置闭环，再补充高级能力。

没有使用量数据，不能把低频功能直接认定为无用。此次建议移除的是独立入口和未兑现的交互承诺，保留仍有价值的底层能力及历史配置。工作区已有多处未提交修改，实施时应基于当时实际代码继续，不覆盖其他改动。

## 新导航与功能去向

| 新一级入口 | 二级功能 | 原入口处理 |
|---|---|---|
| 通用 | 时间显示、常用标签 | 替代“外观与默认值”；需求链接模板移到集成 |
| 工作区与同步 | 当前工作区、工作区列表、添加已有仓库/克隆、Git 远端、提交身份、分支 | 合并工作区、Git 远端、Git 与身份；自动提交暂不展示 |
| 团队与访问 | 局域网地址、只读分享/角色协作、访问者角色 | 保留团队协作；不再暴露第二套局域网权限开关 |
| 集成与通知 | 外部需求与迭代、反馈平台、通知渠道、扩展连接 | 合并 MCP 中心与反馈集成；接收需求链接模板 |
| 版本规则 | 基线内容锁定、设基线前变更日志要求 | 保留规则能力，名称直接体现用途 |
| 维护与诊断 | 软件更新、回收站、操作日志、上传限制、索引维护 | 合并更新、回收站、日志、服务与网络；接收重建索引 |

“维护与诊断”内部使用二级导航或页签，避免把所有表格和表单一次加载。默认进入通用；从业务界面进入时直接定位相关设置。若通用设置尚未补齐效果，过渡期默认进入工作区与同步，不展示空页。

## 合并、下沉与暂缓清单

- **合并 Git 配置**：远端地址、身份、分支在一个页面完成。实际同步、冲突处理沿用现有 Git 面板，设置页提供状态与跳转，避免建设第二套操作台。
- **合并集成入口**：按“需求与迭代、反馈、通知、扩展”组织；MCP 作为连接方式显示。服务定义可供多个能力引用，禁用连接前展示受影响能力。
- **下沉维护工具**：日志、回收站不再占一级入口；保留原型删除后的恢复入口及项目上下文跳转。
- **下沉高级字段**：工具映射、JSON、超时、自定义请求头、配置键放在“高级设置”。常用配置直接提供中文业务标签。
- **暂缓自动提交**：不引入后台自动同步，不将“自动提交”改名为“自动保存”。未来是否开发需单独明确触发时机、提交范围和失败语义。
- **不新增装饰性功能**：本轮不添加主题商城、配置评分、重复总览页、自动清空回收站或无明确恢复边界的一键重置全部。

## 优先升级的功能

### P0：精简入口并纠正误导

1. 落地 6 个分组及旧路径映射。`gitRemote`、`git` 定位到工作区与同步的不同子区；`mcp`、`integrations` 定位到集成对应页签；`softwareUpdate`、`trash`、`oplog`、`server` 定位到维护子页。`lan` 继续兼容进入团队访问。旧链接不能统一退回首页。
2. 去除没有执行链路的自动提交控件；历史配置继续可读，不静默删值，也不因升级而突然开始执行。
3. 区分“尚未检测、检测中、检测失败、无更新、有更新、更新受阻、更新完成待重启”。检测失败不能显示“已是最新版本”。
4. 统一保存反馈：开关即时保存并在失败时回退；相关文本字段组成表单，明确保存/取消；无变更不提交。消除当前 Enter 与失焦可能重复触发保存的问题。
5. 每页说明配置作用范围与生效时机。区分当前工作区配置、本机工作区注册信息、浏览器角色状态、软件目录更新，不虚构统一的全局设置。

### P1：让配置真正可用

**集成与通知**

- 以配置卡展示未配置、已配置未验证、验证成功、验证失败、已禁用；最近验证成功不等于实时在线。
- 根据平台显示必填字段：GitHub/Gitee 的组织与仓库，GitLab 的项目标识，自建平台的 API 地址；平台切换保留草稿，不直接清除旧值。
- 通知平台选择后继续配置对应发送方式、目标和必要凭据；具体凭据字段与写入能力先核对现有秘密存储接口，不能将凭据写入普通工作区配置或 Git。
- 区分连接测试与发送测试：连接测试尽量只读；发送测试显示目标与内容，用户明确点击后才发送。
- 需求链接模板提供编号输入与链接预览；仅验证和预览，不自动访问或回写外部需求。
- 复用现有 MCP 连接测试；工具映射和 JSON 保留为高级模式。企业微信通知与正式发版邮件明确区分，项目收件人与邮件模板仍在项目配置中维护。

**通用**

- 时间显示接入已有时间格式工具，覆盖日常列表和详情；需要精确时间的日志继续显示绝对时间，并说明这一例外。
- 常用标签进入现有标签输入的推荐列表，保留自由输入；不自动给历史版本补标签。
- 沿用现有工作区配置范围。若未来改为个人浏览器偏好，需另行定义覆盖优先级和迁移方式。

**工作区与同步**

- 当前工作区优先展示名称、路径和实际状态；添加操作收进“添加工作区”，在已有仓库与 Git 克隆间选择。
- 展示实际提交身份及其来源，不把空配置误认为没有 Git 身份；分支、远端状态复用现有接口。
- 移除工作区明确说明只取消本机注册，不删除磁盘文件；当前工作区如何退出注册需遵守现有服务限制。
- 页面展示主机人工同步入口，不增加自动同步或自动解决冲突。

**团队与访问**

- 统一展示配置值与当前运行状态；LAN 开关保存后明确是否待重启。
- 沿用免登录、浏览器标识记忆角色、首次仅选游客/研发/测试、后续主机改角规则。IP 仅辅助识别，不当成员身份。
- 展示现有角色的能力说明，访客名称、角色重置或新的项目隔离权限作为后续提案，不自行扩充规则。
- 可见性与操作授权分开处理，服务端鉴权仍为最终边界。

### P2：维护与恢复增强

- 操作日志增加项目、动作、时间筛选；跨全量历史检索必须由后端支持分页和筛选，不能仅筛最近 300 条却声称完整。第一阶段先明确“最近 300 条”范围。
- 回收站增加来源上下文和恢复冲突提示，沿用现有恢复规则；不承诺恢复时覆盖同名版本。
- 索引重建移入故障排查，解释用途并展示结果。没有异常时不把它作为日常主操作。
- 更新页明确“软件更新”与“工作区 Git 同步”的对象区别；复用本地改动保护。不加入强制覆盖、自动重启或未经验证的软件回滚。
- 脱敏诊断导出、完整备份恢复作为后续独立范围，先确认现有能力和数据边界，再纳入承诺。

## 必须保留的约束

- 配置校验以 `src/core/config.js` 为来源；UI 分组调整不必改底层配置键。保存和恢复默认使用同一校验规则。
- 基线锁定及变更日志规则默认不变；原型和变更日志的锁定边界、规格书/标签/附件例外、首版和曾为基线版本的规则豁免均不改变。
- 团队角色不能通过关闭 LAN 只读而获得全部写权限；本机管理权限与远程协作权限不混用。
- 反馈导出保留 Markdown 退路；集成重组不修改外部需求主数据权威、回写字段或正式发版顺序。
- 不将 Git 同步视为备份、验收完成或正式发版完成。
