# 当前开发基线折叠设计

## 背景

项目版本页的“当前开发基线”区域同时展示基线身份、维护信息、相对变更、状态标签和操作按钮。信息本身仍有价值，但默认全部展开会占用较多首屏高度，把下方版本索引与基线版本内容推到视口之外。

本次只压缩该区域的默认展示，不改变基线数据、业务规则或操作能力。

## 目标

- 将“当前开发基线”默认压缩为约 44px 高的单行摘要。
- 让下方版本浏览器和基线版本内容更早进入首屏。
- 保留现有基线详情、状态提示和全部操作，并允许用户按需展开。
- 保持桌面端、窄屏、只读模式和无基线状态可用。

## 非目标

- 不删除基线信息或操作。
- 不修改基线、版本、评审状态和规划摘要的数据模型或 API。
- 不调整项目摘要卡、版本索引、版本详情和工作台的业务逻辑。
- 不持久化用户的展开状态。
- 不新增动画库或通用折叠组件。

## 交互设计

### 默认折叠

存在版本时，当前基线区域默认显示一行摘要：

- “当前开发基线”；无基线时显示“基线状态”。
- 当前基线版本号；无基线时显示“未设置”。
- 基线标题；无基线时显示现有引导文案。
- 现有新版本或待评审等状态提示。
- 位于行尾的展开图标。

摘要行使用现有浅主色背景和左侧主色边线，保持基线状态的视觉识别。整行是语义按钮，鼠标点击、触摸、Enter 和 Space 均可切换展开状态。按钮提供 `aria-expanded` 和关联内容的 `aria-controls`。

页面重新进入或刷新后恢复默认折叠，不写入 URL、个人偏好或本地存储。

### 展开状态

展开后在摘要行下方展示现有内容：

- 维护人、确认时间和关联需求数。
- 相对上一基线的新增、修改和删除数量。
- 当前状态标签。
- 打开当前基线、与上一基线比较、基线历史、标记已读和回滚等现有操作。

展开内容只改变呈现，不重新请求数据。现有加载失败提示、权限控制、确认流程和操作反馈保持不变。

### 无基线状态

项目存在版本但尚未设置基线时，折叠行显示“基线状态 · 未设置”及现有引导文案。展开后继续提供当前可用的基线历史等操作，不新增设置基线快捷逻辑。

## 布局与响应式

- 桌面端折叠行目标高度约 44px，内容保持单行。
- 基线标签和版本号始终可见；标题在空间不足时省略。
- 状态标签和展开按钮不与版本号争抢空间。
- 480px 以下允许隐藏被截断的标题，但不隐藏基线标签、版本号和展开状态。
- 展开内容沿用现有换行规则；操作按钮在窄屏自然换行。
- 版本浏览器结构和现有高度计算保持不变，仅通过折叠区域释放首屏垂直空间。

## 实现范围

预计只修改：

- `web/src/pages/ProjectVersions.tsx`
- `web/src/pages/ProjectVersions.module.css`

页面内部增加一个布尔展开状态。现有基线内容和操作节点移动到可折叠内容容器中，不提取新组件，不修改模型文件。

## 无障碍

- 折叠触发器使用原生按钮语义，并保留清晰的 `:focus-visible` 样式。
- `aria-expanded` 与当前状态同步，`aria-controls` 指向展开内容。
- 展开图标仅作视觉辅助，不单独承载状态。
- 触发区域最小高度为 44px。
- 状态继续同时使用文字和颜色表达。

## 验证与验收

### 自动验证

- 前端生产构建通过。
- 现有全量 Node 测试通过。

### 浏览器验收

在桌面端和 390px 窄屏验证：

- 页面初次打开时基线区域默认折叠。
- 折叠状态只占单行，下方版本内容较改动前更早露出。
- 鼠标点击、触摸、Enter 和 Space 均可展开与折叠。
- 展开后原有信息、标签和操作完整可用。
- 刷新页面后恢复默认折叠。
- 无基线、只读和规划摘要加载失败状态没有回归。
- 页面无横向滚动，控制台无新增运行时错误。

## 范围边界

本次不删除任何基线能力，也不重排项目摘要或版本浏览器。若后续仍需进一步压缩首屏，应另行评估把基线入口合并到项目摘要或版本浏览器顶栏，不在本次变更中提前实现。
