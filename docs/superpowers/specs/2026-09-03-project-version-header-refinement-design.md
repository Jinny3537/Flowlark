# 项目版本页头精简设计

## 背景

项目版本页当前在标题区上方单独放置“返回”按钮，并在标题区下方展示一张五列项目摘要卡片。返回入口与标题层级脱节，项目类型“项目版本”和项目名称之间的关系不够清晰；项目代码、最新版本、当前基线、基线关系和最近更新时间又与下方版本内容重复，造成页面顶部过高、信息焦点分散。

本次采用已确认的“面包屑 + 主标题”方案，精简页面顶部并强化导航和标题层级。

## 目标与成功标准

- 将返回入口、页面类型和项目名称组织成清晰的上下文路径。
- 删除整张项目摘要卡片，使版本内容更快进入首屏。
- 保留项目版本页现有操作、数据、权限和路由行为。
- 长项目名及窄屏下不出现横向溢出、文字遮挡或操作按钮截断。
- 变更仅作用于项目版本页，不改变其他详情页的共享页头表现。

## 页面设计

### 导航与标题

页面顶部第一行展示轻量上下文导航：`← 项目列表 / 项目版本`。

- “项目列表”是可点击的返回入口，继续导航至 `/projects`。
- 左箭头保留返回语义，并与文字组成一个可发现、可聚焦的操作目标。
- “项目版本”是当前位置文本，不可点击，不再作为单独的绿色眉题悬浮在项目名称上方。
- 第二行以项目名称作为页面唯一的一级标题。
- 不再展示项目说明或通用说明占位，避免在精简后的标题区重新堆叠项目信息。
- 右侧继续展示页面现有操作按钮，不改变按钮顺序、权限或点击行为。

### 信息精简

删除 `项目摘要` 区域及其全部展示字段：

- 项目代码
- 最新版本
- 当前基线
- 基线关系
- 最近更新

下方现有“当前开发基线”模块直接承接页头。版本号、基线和更新时间等信息仍可在后续版本模块中查看，不迁移到新的卡片或标签中。

## 实现边界

采用页面级实现，不修改共享 `PageHeader` 组件，避免改变交付详情、需求详情和迭代详情等其他页面。

预计只修改：

- `web/src/pages/ProjectVersions.tsx`：增加页面级上下文导航；移除该页传给共享页头的返回与眉题配置；删除项目摘要区域。
- `web/src/pages/ProjectVersions.module.css`：增加上下文导航样式；删除项目摘要样式和对应响应式规则；收口页头与下方内容间距。

不新增依赖、组件抽象、接口调用或持久化状态。

## 交互与无障碍

- 上下文导航使用带可访问名称的真实按钮或链接，不使用不可聚焦的点击容器。
- 返回操作继续使用 React Router 导航，不替换浏览器历史，也不改变目标路径。
- 键盘焦点沿用现有按钮焦点样式；点击目标在窄屏下保持至少 44 像素的可操作高度。
- 项目名称继续使用 `h1`，下方内容保持现有顺序，避免破坏标题层级。
- 分隔符仅用于视觉表达，对辅助技术隐藏，当前位置使用普通文本表达。

## 响应式行为

- 桌面端：上下文导航位于项目名称上方；标题区与操作区左右排列。
- 窄屏端：沿用共享页头现有纵向布局，操作区换至标题下方并允许换行。
- 长项目名允许在标题区域自然换行，不挤压操作按钮。
- 删除摘要卡片后，不保留空白占位或仅针对摘要卡片的旧断点规则。

## 数据流与错误处理

本次不修改数据流。项目加载、版本加载、只读提示、空状态和错误状态继续沿用现有逻辑。

- 项目名称缺失时仍回退显示路由中的项目标识 `slug`。
- 项目或版本请求失败时继续展示现有错误反馈。
- 只读模式只影响现有写操作，返回和浏览行为保持可用。
- 删除摘要展示不会删除或修改任何项目字段、版本数据或服务端接口。

## 验证

- 运行 `npm run build --prefix web`，确认 TypeScript 与生产构建通过。
- 在桌面视口检查上下文导航、项目名称、右侧操作和“当前开发基线”模块的垂直衔接。
- 在窄屏视口检查长项目名、按钮换行、返回入口触控尺寸和横向溢出。
- 验证“项目列表”返回 `/projects`，草稿箱、新建版本和继续处理最新版本行为保持不变。
- 检查页面中不再出现 `aria-label="项目摘要"` 及其五个展示字段。

## 非目标

- 不删除项目模型中的代码、优先级或其他字段。
- 不调整项目列表、版本工作台或其他详情页页头。
- 不改变版本筛选、比较、回滚、废弃、删除或基线管理能力。
- 不改变现有主次按钮策略或引入新的页面操作。
- 不进行全局样式重构或无关命名整理。
