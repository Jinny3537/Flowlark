# Flowlark 0.8.0 需求与归档原型协作升级

目标：外部制作/修改原型，Flowlark 归档并关联需求；研发和测试按迭代中明确采用的版本协作，反馈驱动下一次外部修改。

## 实施范围与顺序

1. 核心模型与同步：requirements.js、service.js。增加本地分析、生命周期、历史；同步预览及已删除需求排除。软删除保留原记录与编号，防止历史引用失效。冻结或进行中迭代引用阻止删除；不删除源平台内容。
2. 归档关联：复用版本 requirements 和 changes，补充每条需求的页面/范围说明；NewVersionDialog、WorkbenchPrimitives、RequirementDetail 支持归档及双向跳转。
3. 开发依据与协作：以 milestone.items 的明确版本为依据，不随最新归档或项目基线自动切换；复用迭代编辑和进行中范围变更。team.js 扩展不可变协作记录的需求、回复、处理版本和确认结果，前后端按角色校验。
4. 页面与管理：需求详情汇总原型、迭代、团队记录与标注反馈；列表提供待处理和归档/回收站入口，支持单条归档、删除、恢复。更新 CLI、API、文档及版本号。

## 约束

- 工作区已有未提交改动，增量修改，不回退。
- 保持原型基线锁定规则；历史基线关联修改仍受现有规则限制。
- 源字段沿用原同步策略，本地分析独立字段保存；不自动推断外部业务状态。
- 采用版本缺失显示未确定，旧数据不自动获得新确认记录。
- 角色是现有浏览器协作身份，不宣称实名认证。游客保留现有评论权限，不能提交研发/验收结果。
- 回收站采用原记录 deletedAt 标记，保留编号、关联及所有历史；不提供永久删除。
- 不执行发布、部署、远端同步或消息发送；本次升级交付本地代码。

## 验证

新增真实文件/API测试覆盖同步排除、本地分析保留、删除阻止/恢复、关联元数据、迭代依据不漂移、协作角色和回复链校验。执行 node --test 和 web/npm run build；隔离临时数据仓库执行浏览器协作闭环与回收站回归，不操作用户业务数据。

验收场景：需求关联 v1.3，提出问题；外部修改后归档 v1.4，记录处理版本；迭代采用 v1.4；归档 v1.5 后开发依据仍为 v1.4；测试记录结果并可追溯；删除后不被同步复活且可恢复。
