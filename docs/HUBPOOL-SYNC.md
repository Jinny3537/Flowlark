# HubPooL 全项目同步

在设置的 MCP 服务中配置需求池地址和配对码；在需求能力中选择 HubPooL、启用能力，并选择“全部项目”。无需项目 ID。仍可选“指定项目”限制范围。

同步先查询项目目录，再逐项目查询需求、读取详情与版本归属。后续新增源项目自动纳入需求查询范围。同步只导入和更新需求，不在项目模块创建、修改或恢复项目；需求仍保留源项目 ID 和名称。需求使用 HubPooL 稳定 ID 标识，避免不同项目的展示编号相同造成覆盖。

需求页面的“同步需求池”先展示项目数量、项目内需求数量、逐条差异与错误，确认后导入或更新。已存在的本地分析、截止日期和回收站记录保留。单项目列表失败会明确报告，其他项目继续；需求详情失败逐条报告。重试失败需求不会回滚成功结果。

单次同步缓存项目和版本查询；每次重新同步都会重新取源数据。源项目目录仅用于查询需求范围，不写入本地项目模块，也不回写源系统。

同步范围包括需求字段、源项目归属以及需求所属版本名称。发布计划、资料正文和原型文件不自动转换成本地原型版本。HubPooL 目前每项目最多返回 500 条且无分页；达到上限或源端返回截断提示时显示不完整警告，不能视为完整台账。同步不根据源列表缺失自动删除本地数据。

## 项目删除与恢复

项目卡片的“更多项目操作 → 删除项目”会把项目目录（包含全部原型版本、资料、基线指针）移入项目回收站。独立需求、迭代和 HubPooL 源数据保留。项目页的“项目回收站”可恢复到原路径；路径或代码冲突时拒绝覆盖。需求同步不创建本地项目。恢复项目后重新纳入正常项目列表。

## 源需求回收站

HubPooL 的列表响应不含回收站字段，所以搜索与同步逐条读取详情，以 `trashedAt` 判断源需求是否已删除。回收站需求不出现在搜索结果中，也不能直接导入。同步会把已误同步的本地副本列为“源端已删除，移入本地回收站”，确认后可恢复地移除，保留分析与历史关联。预览与执行之间源状态变化时拒绝使用旧预览。源端恢复后，本地已删除需求仍需用户先从本地回收站恢复，避免覆盖本地主动删除意图。
