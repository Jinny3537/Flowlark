# 从需求和原型进入迭代，再准备交付

需求说明要解决什么，原型表达具体方案，迭代组织这次一起做的需求与版本，交付包固定本次材料。

## 查看功能之间的联系

需求详情、原型工作台和项目版本摘要新增“关联去向”。点击数量可展开具体需求、原型、迭代或交付，再进入相应详情。候选范围、采用版本、历史采用和已取消范围分别展示。

从关联入口进入其他页面后，顶部显示来源及返回入口；从迭代范围进入需求或原型，再返回时会定位原范围行。关联查询失败会提供重试，不会显示成“没有关联”。

## 从需求或原型安排迭代

1. 在需求详情点击“安排到迭代”，选择关联的项目和原型版本；或在原型工作台点击“加入迭代”，选择本次包含的需求。
2. 选择已有规划中 / 评审中的迭代，或者选择“新建迭代并加入”，填写迭代标识、标题和可选周期。
3. 点击“核对范围”。同一映射不会重复加入；同需求同项目已有其他候选版本时，明确选择保留还是替换。
4. 确认后点击“查看迭代”，也可以留在原页继续工作。

取消新建不会留下空迭代。页面过期、范围已修改或阶段已锁定时，系统拒绝旧提交并要求重新核对。新入口只安排已经关联的需求和原型，不自动创建业务关联。

规划期可暂存多个候选版本，冻结前仍按既有规则解决同需求同项目的版本冲突。冻结、进行中或历史迭代不能从快捷入口直接改写范围。

## 从迭代准备交付

迭代详情先展示“本次需求与原型”。需求编号与标题、原型版本都可点击；统计区分需求数、项目数与去重后的版本数。

点击“准备交付包”，来源迭代会带入现有交付流程：确定范围 → 检查材料 → 填写交接说明 → 冻结并创建。

检查时可以点击“补充材料”进入对应原型，补充后点击“返回交付准备”。当前标签页会按仓库暂存已填内容，返回或刷新后恢复输入并重新检查材料。需要中断时选择“暂存并关闭”；主动清除输入时选择“放弃草稿”。暂存内容不进入 Git，关闭浏览器标签页后不保证继续保留。

创建后的交付包列在迭代详情的“本迭代交付”中。多次交付分别保留，可返回来源迭代，也可查看源版本的当前资料。

## 保留的边界

- 最新归档、当前项目基线和迭代采用版本仍分别表达不同事实。新增归档不会自动改变迭代范围。
- 创建交付包不等于研发接收、测试通过或正式上线。“导出迭代包”和“正式发版”继续使用各自入口。
- 交付关联按冻结时明确保存的范围匹配；同一原型关联的其他需求，不会被推断为已包含在该交付中。
- 只读、研发和测试角色按既有权限浏览关联，不能通过新入口修改范围。
- 原型、交付或需求的历史资料缺失时保留可证实的关系并提示核对，不自动修复或删除历史引用。
- 显式创建交付继续使用已有通知入队逻辑；浏览、暂存或跨页跳转不自动发版或发送消息。

## 写入被占用时

安排和编辑迭代使用内容修订校验及本机写锁，正常结束或业务失败都会释放锁。如果进程被强制终止留下锁文件，先确认该仓库没有正在写入的 Flowlark 进程，再由主机清理 `.flowlark/cache/milestone-locks/<迭代标识>.lock`，重新读取范围后操作；不要在写入进行时清理。
