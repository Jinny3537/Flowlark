# 需求与归档原型协作（0.8.0）

需求、原型、迭代与交付之间的关联入口、就地安排及交付续办，见[功能关联操作指南](MODULE-WORKFLOW.md)。

Flowlark 保存外部工具制作、修改完成的原型。典型流程是：准备需求 → 外部修改 → 导入归档并关联需求 → 查看与反馈 → 外部修改后再次归档 → 确认迭代采用版本 → 开发与验收跟进。

## 产品经理

1. 在需求页创建或同步需求。源平台原文仍由源平台维护；将补充分析、待确认事项及决策理由写入“本地分析”，同步不会覆盖该字段或本地截止日期。
2. 在项目中导入原型文件。在关联需求编辑器中选择需求，填写对应页面位置、本版承载范围，并在变更日志中记录具体变化。一个归档版本可以关联多条需求，一条需求可以关联多个项目和版本。
3. 在需求详情的“协作与开发依据”查看全部归档，也可“关联已有归档”。关联和解除关联继续受原有基线锁定约束；已作为冻结、进行中或历史交付依据的关联不能直接移除。
4. 用“安排到迭代”将归档版本加入规划中或评审中的候选范围。同一需求在同一项目的新选择会替换该迭代中的旧候选版本。冻结、启动和进行中范围变更继续从迭代页处理。
5. 在需求下查看反馈，外部修改后归档新版。回复原始问题，选择“已在归档版本处理”并填写处理版本，等待研发或测试核对。

## 研发与测试

需求详情优先展示相应角色的使用提示。先找到本次迭代，再打开其采用版本；不要直接把最新归档当作开发依据。

- 研发可以评论、记录“已确认开发依据”“开发中”“开发完成”。
- 测试可以提交问题、记录“验收通过 / 不通过”。
- 研发和测试可在产品指定的处理版本上确认问题解决；若仍有问题，选择“仍有问题”。重新打开后，需产品重新记录处理版本，才能再次确认。
- 产品可以记录问题处理与回复，但不能冒充测试提交验收结果。
- 游客保留现有团队模式中的评论权限；只读分享不允许提交。

这些是浏览器协作身份记录，不是实名签字或企业账号认证。服务端以会话角色判断权限，忽略请求伪造的角色和操作者字段。

## 最新归档与开发依据

“最新归档”按关联版本的归档时间展示，废弃版本不作为最新候选。

“采用版本”直接来自迭代保存的需求、项目、版本对应关系。规划中和评审中的范围标为候选；已冻结、进行中、已交付和已归档迭代保留各自明确的采用版本。

上传新版、切换项目基线、提交开发进度、记录验收通过，都不会自动改写迭代范围。多个迭代可能采用不同版本，界面分别展示，不猜测哪一个代表所有项目的统一开发依据。

版本详情中的原型进度只说明归档和原型确认情况，不等同于研发完成或上线。研发任务远端状态显示最后同步时间；验收记录保留具体版本、角色、内容和结果。

## 反馈与历史

协作问题、回复和处理结果以独立不可变文件保存在 `.flowlark/collaboration/`，可随 Git 同步。需求可以汇总跨版本问题；普通回复不会改变已解决或待确认状态。

本机标注反馈仍属于原有缓存草稿。产品可从需求详情将其转成协作问题，持久保存文字和标注坐标。截图仍按原草稿机制保存，不作为跨机器持久附件；删除草稿不会删除已转存的问题文字和坐标。

本地分析和源字段更新保留字段前后值；归档、删除、恢复保留操作记录。旧数据不会补造历史或确认人。

## 同步与删除

同步先展示字段差异。确认时再次校验本地记录和源差异，发生变化的条目跳过并提示重新预览。部分失败可以单独重新预览和重试。源平台发生删除时不会推断为应删除本地需求。

- **归档**：移出活跃列表，保留关联；仍可同步。
- **删除**：在原需求记录中写入 `deletedAt`，进入“需求回收站”。原型、迭代和历史交付记录不删除；编号保持占用，防止历史引用指向另一条需求。
- **阻止删除**：冻结或进行中的迭代仍引用需求时，先通过现有迭代流程调整范围。
- **恢复**：清除删除标记，保留之前的归档状态、内容和关联。不存在覆盖同编号新记录的入口。
- **外部需求**：仅删除本地副本；同步跳过回收站编号。显式导入也会提示先恢复，防止自动复活。

不提供永久删除，也不会向外部需求平台发送删除请求。

## CLI

```bash
flowlark req list
flowlark req show REQ-8 --json
flowlark req link REQ-8 orders v1.4 "订单列表" --desc "批量关闭异常交互"
flowlark req notes REQ-8 --desc "待确认并发修改场景"
flowlark req impact REQ-8
flowlark req archive REQ-8
flowlark req unarchive REQ-8
flowlark req delete REQ-8
flowlark req trash
flowlark req restore REQ-8
flowlark req sync           # 仅预览
flowlark req sync apply     # 明确执行同步；浏览器支持逐条过期校验
```

数据格式为兼容性扩展，旧记录按缺省值读取，不要求批量迁移。需求、迭代、协作记录均纳入 Git 受管路径。
